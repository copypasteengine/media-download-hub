# Media Download Hub

Cobalt 视频解析与下载、串行下载队列、Telegram / 飞书机器人和中文管理后台。通过 Docker Compose 部署；部署后的分类、平台 Cookie、代理、机器人和备份都在后台配置。可运行在服务器、云主机、支持 Docker 的个人电脑或 NAS 上，不依赖飞牛系统或固定媒体分类。没有一键部署脚本。

旧版部署改名升级前，请先阅读 [项目名兼容说明](docs/operations.md)，保留原 Compose 项目名以复用配置卷。

## 部署

需要支持 Linux 容器的 Docker Engine 或 Docker Desktop，以及 Docker Compose v2。支持 ARM64 / AMD64 构建；ARM64 已在 RK3566 Linux 主机上验证，其它主机与 Docker Desktop 尚未做完整实机验证。Docker Desktop 的媒体目录需先授权文件共享。

1. 将整个工程放到服务器，将 `.env.example` 复制为 `.env`。
2. 在 `.env` 设置 `BIND_IP` 为服务器局域网 IP，`MEDIA_ROOT` 为已挂载的媒体目录，`STATE_ROOT` 为已创建的持久化任务目录。另外创建 Telegram 缓存目录（默认为 `STATE_ROOT` 下的 `telegram-api`；可用 `TELEGRAM_CACHE_ROOT` 指向外接盘）。这些目录都必须存在，且容器有写权限。不要对整个媒体盘递归修改权限。
3. 执行标准 Compose 命令：

   ```sh
   docker compose up -d --build
   ```

4. 在可信局域网打开 `http://服务器IP:9072`，首次创建管理员。进入「下载分类」，用「浏览」选择保存文件夹，勾选确认存储位置并保存。Cobalt 入口自动识别，内部下载不依赖对外入口。
5. 在后台配置本服务专用代理、导入平台 Cookie；在「机器人」填写凭据、启用并绑定本人账号。Telegram 大文件下载在同页填写自己的 API ID / API Hash 并打开开关，无需修改 Compose 或登录个人账号。
6. 转发 Telegram 视频后点击保存位置才会下载；同一相册选择一次。分类直接使用后台动态配置，重启保留待选择的视频。详见 [Telegram 视频](docs/telegram-video.md)。

默认端口：9070 为 Cobalt 页面，9071 为兼容 API，9072 为管理后台。默认只绑定 127.0.0.1；按需调整 `.env`。管理后台包含账号与任务管理，不建议直接暴露为公网 HTTP。媒体公开入口的反向代理或 FRP 指向 9070。

构建需要访问官方镜像仓库和 npm；Telegram 大文件服务和可选浏览器还需要 Alpine 软件源。运行时代理通过网页配置，仅供本项目使用，不修改宿主机的全局代理。基础镜像锁定摘要，npm 使用 lockfile。

## 动态分类与路径映射

「下载分类」可以新增、重命名、停用和删除分类。每项配置：

- 按钮名称：两种机器人的菜单都会自动更新。
- 保存位置：点击「浏览」，选择已授权存储位置及其子目录；支持面包屑导航和新建文件夹，无需手填容器路径。
- 默认分类：直接发链接、没有先点按钮时使用。
- 隐藏标题：通知中隐藏视频标题和来源；**不等于 主机文件或媒体库访问权限**。
- 命令别名：可选，日常操作只点菜单即可。

默认只有「视频 → Videos」，可以全部按自己需求调整。分类使用稳定内部 ID，改显示名称不影响路径和任务归属。新增和改名不会打断正在下载的任务；正在使用的路径不能改动、停用或删除。改路径只改变后续保存位置，不会搬动或删除已有文件。旧菜单、已删除分类或失效的待输入状态不会悄悄改存到默认目录。

目录不能互相嵌套，不能包含 `..`，也不能通过符号链接逃出媒体挂载。确认映射后使用每个分类的 `.cobalt-volume` 标识和文件系统类型检查；磁盘或标识消失时停止写入。它不能替代宿主机磁盘健康检测。

### 存储位置与多硬盘

目录浏览器展示显式挂载给 manager 和 queue 的存储范围。Docker 无法直接访问未挂载的宿主机文件夹，这与工程叫什么名字无关。默认 `.env` 的 `MEDIA_ROOT` 是宿主机目录，`DOWNLOADS_MOUNT` 是容器内挂载路径（默认 `/downloads`），`STORAGE_NAME` 是页面显示名称；三者都可以修改。

若要选择其它硬盘或目录，在 manager 和 queue 两个服务中添加相同挂载，例如：

```yaml
- type: bind
  source: /mnt/archive
  target: /archive
  bind: {create_host_path: false}
```

然后 `.env` 配置两个存储位置：

```dotenv
STORAGE_ROOTS=[{"id":"main","name":"视频盘","path":"/downloads"},{"id":"archive","name":"归档盘","path":"/archive"}]
```

执行 `docker compose up -d` 后，后台浏览器出现「视频盘」「归档盘」，可直接点选目录。存储 ID 用于保存映射，改显示名称无妨；迁移时尽量保持 ID 一致，路径可以重新配置。不存在的挂载、符号链接和越界路径会拒绝访问。不应为方便浏览把宿主机整个 `/` 挂入容器。

主机账号、共享权限及媒体库仍由操作系统 / 媒体软件管理，本项目只保存文件。

## 界面、绑定与网络

「运行概况」只显示服务、磁盘及进行中的任务；「下载任务」提供历史记录、状态筛选、搜索、分页和重试。页面自动更新状态，未保存的表单会保留编辑内容并提示。

Telegram：保存 Token 并连接成功后，扫码或点击机器人链接，点“开始”即完成绑定。飞书：二维码打开机器人会话；点击“复制绑定消息并打开飞书”，粘贴发送即可。绑定成功后后台自动更新，无需手打命令。二维码在服务本地生成，不调用第三方二维码网站。已绑定账号不会因升级而解绑。

「网络与代理」自动根据当前浏览器主机和 Compose 的网页端口识别 Cobalt 入口。外部反向代理使用不同域名/端口时可手动指定。Cobalt 网页 API 与下载通道同源，队列只通过容器内服务名连接，不依赖此入口设置。

新部署默认直连，无内置代理节点。「网络与代理」以紧凑列表展示名称、协议、来源、检测延迟与当前使用状态，不展示或要求编辑 JSON，也不向普通节点接口返回密码或完整配置。

- 「导入节点 / 订阅」区分订阅地址、单个节点分享链接和订阅文件。单独导入会追加节点，不清空其它来源；订阅支持命名、更新和删除。
- 节点默认每页 20 个，可切换 50 / 100 个；名称、协议与地址搜索及来源筛选覆盖全部节点，翻页不改变当前连接。
- 点击节点「使用」切换并进入手动模式；点击「自动选择」检测可用节点后选择延迟较低的节点。现有代理会自动迁移到列表并保持选中。
- 延迟检测启动独立临时代理，实际访问 YouTube 检测地址；不会切换当前代理。检测串行执行，单节点最多约 14 秒，每轮最多 30 个节点，可随时取消；其它节点可以单独点检测。
- 自动模式每 10 分钟检查一次，当前节点可用时保持连接，失效才寻找替代。队列正在下载时等待空闲再切换；没有可用节点时保留原配置，不自动切成直连。
- 支持 VLESS、VMess、Trojan、Shadowsocks 常见链接、Base64 订阅、Clash `proxies` YAML 和 Xray 订阅文件。暂不支持 Hysteria2、TUIC、Clash 策略组、插件及链式节点的自动转换；不支持的节点会提示原因。

订阅 URL 需要服务器可以直连；无法直连时可在自己的浏览器下载订阅文件再上传。订阅内容目前手动更新，节点连通性检查与订阅更新是两件事。所有代理及检测均限本项目使用，不影响宿主机网络。

## 平台账号

默认通过后台粘贴 Cookie 或上传文件。支持 Cookie 请求头、Netscape `cookies.txt`、Cookie JSON 数组或 `{ "cookie": "..." }`；导入时验证账号，成功后才替换旧登录态。Cookie 不回显，不写入日志。

普通新标签页登录后，网页不能跨站读取其 Cookie。因而如果希望直接在后台操作官方登录页，需要可选的临时浏览器：

```sh
docker compose --profile browser-login up -d --build
```

同时在 `.env` 设置 `BROWSER_LOGIN_ENABLED=true` 并重建 manager 容器。默认不启用此组件、不占用 Chromium 内存。远程画面仅用于展示运行在服务器上的登录页，扫码/验证后提取对应平台 Cookie；不是下载所必需的远程桌面。关闭时临时资料删除，15 分钟自动超时，无媒体盘或配置卷挂载，不开放 VNC/CDP 宿主机端口。Google 可能拒绝服务器浏览器登录，遇到这种情况使用 Cookie 导入。

这不是 Google OAuth，也不提供绕过验证码、MFA、付费权限或 DRM 的功能。账号检查正常每 6 小时、异常每 15 分钟，连续失败才通过绑定的机器人提醒。失效后需要重新登录。

## 下载与机器人

Telegram 单聊与飞书长连接，只有绑定的本人能提交下载。点目录按钮后发送链接即可。新 Bot 凭据会重置旧绑定；后台也能手动解除绑定。每个通道仍是单用户绑定，尚无多用户角色管理。

串行下载，临时文件和最终文件同目录所在磁盘，完成后原子发布；按平台标题、作者等信息命名。提供画质选择、实际分辨率、任务状态、取消和重试。空间阈值、单文件上限在后台设置。支持直接转发 Telegram 视频、视频文件、短视频和视频相册；官方 Bot 接口限单个附件 20 MB，超限会明确提示。附件保存收到的文件，不重新编码，画质设置仅影响平台链接下载。暂不提供字节级断点续传或 MTProto 私有频道视频下载。详见 [Telegram 转发视频](docs/telegram-video.md)。

## 数据与迁移

- Docker `config` 卷：后台密码哈希、平台 Cookie、机器人凭据和服务设置。
- `STATE_ROOT`：任务记录、绑定、通知去重及登录健康状态，子目录自动创建。
- `MEDIA_ROOT` 及额外挂载：视频和下载临时文件。

后台「备份与安全」手动导出 AES-256-GCM 加密备份，包含配置、平台 Cookie、绑定和任务，**不包含媒体及当前后台密码**。备份口令不能找回；目前不提供定时云备份。备份时短暂停止工作进程以取得一致记录，未完成下载重启后会重新下载，建议空闲时操作。

换设备：复制工程、挂载媒体盘 → Compose 启动 → 创建后台管理员 → 导入版本 2 / 3 备份 → 重新登录 → 检查分类存储位置和入口 → 确认存储映射。新设备后台密码保持不变；确认前队列不写入媒体。旧、新设备不要同时运行同一个机器人。

更新前先备份，再执行 `docker compose up -d --build`。不要使用 `docker compose down -v`，它会删除配置卷。

## 服务结构与开发

Compose 中的 `cobalt` 是独立服务、独立 Dockerfile 和镜像，基于官方 Cobalt 固定版本，带平台适配补丁。`manager`、`queue`、`telegram`、`feishu`、`web`、`proxy` 使用独立 Node 应用镜像；`browser` 为可选 profile。没有 Docker socket、privileged 或宿主机网络依赖。为兼容部分 NAS ACL，只有 manager / queue 添加 DAC_OVERRIDE，且只操作显式挂载的目录。

`app/` 包含队列、机器人和配置加载，`manager/` 包含后台，`patches/` 为 Cobalt 适配，`runtime/` 锁定依赖，`vendor/` 包含对应源码、前端构建产物与经过校验的 Xray，`tests/` 验证分类、目录保护、队列与账号管理等行为。

```sh
npm ci --ignore-scripts --prefix runtime/app
npm run check
npm test
```

测试需要 Node.js 22+，部分测试监听本机临时端口。见 [第三方许可](THIRD_PARTY.md)、[版本记录](CHANGELOG.md)。

开发流程与 GitHub 自动检查见 [CONTRIBUTING.md](CONTRIBUTING.md)，升级、回退和迁移见 [运维说明](docs/operations.md)。
