# Telegram 转发视频

## 使用

1. 在已绑定的 Bot 私聊中点击下载分类。
2. 从 Telegram 其它聊天或频道**转发视频本身**，也可以发送视频文件。
3. Bot 回复任务编号；「我的下载」显示进度，支持取消、重试和完成通知。

也可以不选分类，直接转发到后台设置的默认分类。一次分类选择用于下一条消息；Telegram 同一视频相册的多条视频消息沿用首次选择的分类。不同相册、独立发送的视频应按需要重新选择。私密分类继续隐藏通知中的标题。

优先按视频说明的首行有效文字命名，没有说明时使用原文件名；没有原文件名时使用 Telegram 日期和消息编号。同名文件不会覆盖。重复转发同一文件到同一分类会返回已有任务；不同分类可各保存一份。

附件保存的是 **Telegram 提供的那份文件**，不重新编码。如果发送者上传时已被 Telegram 压缩，无法还原压缩前画质；希望保留上传原文件时，请以文件方式发送。Bot 的清晰度按钮只影响 B站 / YouTube 等平台链接任务。

## 限制和较大视频

本版本使用 Telegram 官方云 Bot API，单个附件下载限制为 20 MB。已知超过限制时会直接说明原因，未知大小在获取文件信息后再次检查。下载、临时文件及成品均在目标分类所属磁盘，不把媒体缓存在主机系统盘。

超过 20 MB 的视频需要后续部署自建 Telegram Bot API Server（local 模式）。官方要求拥有你自己的 `api_id` / `api_hash`，它们与 BotFather 的 Bot Token 不同；申请入口是 [my.telegram.org](https://my.telegram.org/apps)。当前版本尚未包含本地 Bot API 服务，也没有声称绕过 20 MB 限制。得到凭据后才能继续接入并验证大文件；不要把密钥写进 Git 或发到机器人聊天。

仅发送 `t.me/频道/消息编号` 不等于转发视频；Bot 无法仅凭该链接读取个人私聊、任意频道历史或受保护内容。请打开消息后直接转发视频；来源禁止转发时，不提供绕过方式。

## 隐私与恢复

只接受已绑定本人在私聊发送的消息；转发来源不作为授权身份。任务持久化保存文件引用而非包含 Bot Token 的下载地址，重试时重新向 Telegram 获取有效下载地址。任务列表 API 隐藏文件引用；代理只影响本项目。

更换为另一个 Bot 后，旧 Bot 的文件引用无法通用；失败任务需要向新 Bot 重新转发。文件元数据进入加密备份，视频本身仍需单独备份。

参考：[Telegram File / getFile](https://core.telegram.org/bots/api#getfile)、[Local Bot API](https://core.telegram.org/bots/api#using-a-local-bot-api-server)。
