# 1.6.2 项目审查与修复

日期：2026-10-15。

审查范围：Telegram / 飞书的消息、卡片、分类与通知流程；队列去重、重试、会话权限；分类目录与临时文件；管理接口、备份恢复、代理与进程管理代码；现有 NAS 的部署一致性。

## 已修复

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 飞书菜单按钮被拒绝 | 共用菜单改成 `menu:*` 回调，但飞书只接受旧按钮格式 | 支持新菜单回调；飞书使用完整卡片菜单，Telegram 保留点击展开 |
| 飞书裸链接没有响应 | Telegram 的“无分类先确认”改动进入共用 UI，飞书遇到空结果后直接结束 | 为飞书显式保留默认分类；Telegram 仍先确认 |
| 飞书重试缺少完成通知 | 在后台重试已通知过的失败任务，旧 `notified` 标志阻止再次通知 | 与 Telegram 共用按任务尝试次数判断的通知规则 |
| Telegram 误判待选请求满额 | 已提交、已取消的请求也占用 50 个待选名额 | 只统计真正未处理完的请求，保留已处理记录用于相册与重试去重 |
| Telegram 队列客户端行为不一致 | 独立实现将 429 当作永久错误，并发登录可能产生会话竞争 | 两种机器人共用队列客户端；共享登录、保留可重试限流、避免旧 401 清除新会话 |
| 文件被删除后不能再次下载 | 只检查任务是 completed，未检查成品是否仍存在 | 去重前检查实际目标目录和文件身份；已删除或迁移后的旧记录不拦截新请求。相同请求 ID 的重放仍去重 |
| 重试绕过容量限制 | 已有 50 个活动任务时仍能无限重试旧任务 | 新建与重试共用活动任务上限 |
| 旧会话保留旧权限 | 热更新用户密码、私密权限后，已登录会话仍使用原值 | 每次请求校验当前凭据和权限；私密任务列表、详情操作按当前权限过滤 |
| 存储保护不完整 | 不同存储 ID 可映射重叠目录；标识、临时目录被替换为符号链接可能重定向读写 | 按解析后的实际路径检查重叠；检查目录类型，拒绝标识文件和临时目录符号链接 |
| 空间报错显示固定值 | 后台修改文件上限和保留空间后，报错仍写 50 / 20 GiB | 报错使用当前配置值 |

## 验证

本地全部 87 项测试通过，包含管理接口、队列 HTTP 集成测试、文件删除后重新下载、运行中热更新凭据/权限、并发登录、完整飞书菜单回调、超过 50 次已处理转发请求以及目录保护。JavaScript 语法、Xray 校验和、Compose 版本一致性检查通过。

NAS 实际构建的 ARM64 镜像另通过 25 项针对性测试，包括队列 HTTP 集成测试和两种机器人的菜单/分类流程；使用隔离的测试目录及模拟平台，没有创建真实机器人消息或媒体下载。

升级时仅处理本工程的应用容器；Cobalt 和 Telegram Bot API 使用各自独立版本。配置、任务、Cookie、机器人绑定及媒体文件保留。源码内不包含真实部署密钥。

自动测试使用模拟平台和消息事件，验证路由、状态机和文件落盘；平台登录和下载能力仍取决于平台、账号与网络。可选浏览器登录组件的代码已检查，本次未让用户重新进行实际平台登录。
